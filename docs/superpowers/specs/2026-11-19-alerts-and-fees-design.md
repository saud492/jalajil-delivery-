# Alerts, auto-approve, server-side fees and promo codes — design

Agreed with the owner in chat on 2026-11-19 ("قم بالعمل نعم").

## Why
Today the only alert anyone gets is the WhatsApp message to the owner. Shops and
drivers hear a chime only while their app is open on screen, and the customer
never learns that a bill is waiting for approval, so orders stall at every
hand-off. Separately, the delivery fee and the promo code live in the customer
page: the server trusts whatever fee the page sends, and the code is readable in
the page source with "once per phone" checked by nobody.

## Goals
1. **Push alerts (Web Push)** that arrive with the app closed, for shops,
   drivers, the owner, and (where the phone allows) the customer's tracking page.
2. **Guard:** if a new order sits unanswered, the owner is alerted
   (shop silent 2 min, no driver 3 min, customer approval pending 5 min), once each.
3. **Auto-approve limit:** the customer may write "buy without asking me if the
   bill is up to X SAR". Bills at or under X count as approved. Prepay rules still apply.
4. **Fees and promos on the server:** the server computes the fee from the
   destination and settings; promo codes live in a table managed from the
   dashboard and are checked on the server (dates, uses per phone, total uses).

## Non-goals
WhatsApp Business API, SMS, Telegram; driver on/off duty and history (later);
moving opening hours to the dashboard (later).

## Anti-goals
Delaying any API response or the WhatsApp step because of push sending; leaking
customer data in alert text to people who shouldn't see it (drivers see only
area and fee before taking an order, as now); breaking things when VAPID keys
are not set (push simply hides itself).

## Approaches considered
- **Web Push (picked):** free, works on Cloudflare as-is, opens the right
  screen. iPhone needs the app on the home screen (iOS 16.4+).
- WhatsApp Business API: everyone has WhatsApp, but needs Meta business
  verification, approved templates, per-conversation fees and a second number.
- Telegram bot: free but most shops and drivers here don't use Telegram.

## Design
- **Keys:** `VAPID_PUBLIC` / `VAPID_PRIVATE` Cloudflare secrets, generated by
  `node tools/vapid-keys.mjs`. Push is implemented with WebCrypto only
  (RFC 8291 aes128gcm + RFC 8292 VAPID), no libraries.
- **Subscriptions:** table `push_subs` (endpoint unique, keys, kind
  shop/driver/admin/track, ref id). Endpoints: `POST /api/{partner,driver,admin}/push`
  and the `push` action on `/api/track/:token`. Dead subscriptions (404/410) are deleted.
- **Sending** never blocks the response: it runs in `waitUntil`.
- **Events:** new order → its partner shops, all drivers, owner. Order stage
  changes (computed before/after each action) → approve/prepay: customer;
  prepay_check: owner; buying: the assigned driver; onway: customer; cancelled:
  driver and shops. Part ready → driver. Part rejected → owner and driver.
  Admin assigns a driver → that driver. New report → owner.
- **Guard sweep:** runs at most every 30 s, triggered by any API call and by
  `/api/cron` (protected by `CRON_SECRET`), which a tiny separate Cloudflare
  Worker with a 1-minute cron calls (`cron/`). Each guard fires once per order/part.
- **Apps:** each app gets a "🔔 فعّل التنبيهات" control; on an iPhone that hasn't
  installed the app it explains "add to home screen" first. Admin gets a manifest
  and service worker so it can be installed. Service workers show the
  notification and open its link on tap.
- **Auto-approve:** `orders.auto_approve` (SAR, optional); shown in the form,
  the WhatsApp message, the tracking page and the driver's card.
- **Fees/promos:** settings `delivery_fee` (8) and `out_fee` (10); table
  `promos` (code, discount 0–1, from/to dates Riyadh, uses per phone, max uses,
  active), seeded with the current `JALAJIL` 50% on 2026-11-20. `/api/shops`
  returns the fees and whether a promo runs today (never the code);
  `POST /api/promo` checks a code for a phone. `saveOrder` recomputes fee and
  fee_full and drops an invalid promo. The page keeps its own numbers only as a
  fallback when the API is down.
